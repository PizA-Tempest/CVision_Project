# To-Be-Documented Methods & Known Conflicts

Running lists for the CVision codebase — originally Feature #1 (Job
Fetching from External APIs), extended in Part 4 to cover the Feature 3
code inherited for integration:
methods the code needed that the documents don't define, and places
where the documents (or the original admin.py) disagree with each
other or with what the code actually needs to do. Both get updated as
each remaining file (job_controller.py, scraper_service.py,
scraper_controller.py, scraper_ui.py, admin.py) is built.

## Part 1 — To-Be-Documented Methods

methods in `CVision_MethodDesc_TestPlan_TestRecord.docx`, and do not
appear in any of the four UC-F1 sequence diagrams. Each was added
because the code needed it to actually run, not because the documents
called for it.

Line numbers are deliberately omitted — they'll drift as the files
change. Look up the method by name in the file listed.

### Not on this list, and why

- **`db.query()` / `db.execute()` / `db.transaction()`** — these are M-030/M-031/M-032, already documented. Any module (including a UI file) can call them directly for a simple read/write without needing its own wrapper method — e.g. the Log tab reads `log_entry` via a direct `db.query(...)` call rather than a `get_recent_logs()`-style addition, per the decision on 2026-07-25.

## Part 2 — Minor Conflicts / Inconsistencies

Every entry is: what disagrees with what, why it matters, and the
solution or assumption applied in the code today. None of these block
the current files from working; they're flagged so a human reviewer
can confirm or correct the call later — ideally by updating the source
documents once a decision is confirmed, rather than leaving the code
as the only record of it.
